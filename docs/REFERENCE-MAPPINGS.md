# 基础映射运行时设计

MongoDB 是校区、院系和课程分类的唯一真源。Redis 只负责加速读取，不是权威数据源。Go 代码中保留的静态映射只用于数据库迁移种子和不依赖外部服务的单元测试，不能作为运行时新增数据的存储位置。

## 查询流程

1. 查询对应的 Redis Hash；
2. Redis 未命中或暂时不可用时查询 MongoDB；
3. MongoDB 查询成功后，同时回填 Redis 中的 `name → code` 和 `code → name`；
4. 批量组装课程时按映射类型使用 `HMGET`，避免为每个编号单独请求 Redis。

## 写入流程

1. 通过 `mapping_counter` 分配编号并写入 MongoDB；
2. 如果当前操作位于 MongoDB 事务中，先提交整个事务；
3. 事务成功后才更新或重建 Redis。

校区必须预先存在。创建、修改和审批提案时可以选择多个已有校区，但不能自动注册未知校区。院系和课程分类可以在提案审批通过时创建。

## 启动预热

服务启动时从 MongoDB 读取全部映射，在 Redis 临时键中构建六个双向 Hash，全部完成后通过一次 Lua 操作切换为正式键。因此，并发实例只能看到完整的旧快照或完整的新快照，不会读到只写了一半的数据。

## 历史同名编号

部分旧静态列表中，同一个显示名称对应多个历史编号。迁移时保留全部 `code → name`，保证旧业务数据仍能解析；`name → code` 只指向一条标记为 `canonical` 的记录，并选择最小的历史静态编号作为 canonical。

如果线上动态编号与旧静态编号发生名称冲突，不能把它当作历史别名，也不能自动覆盖。迁移工具必须停止并生成冲突报告，由维护者依据权威业务数据处理后重新执行 `dry-run`。
